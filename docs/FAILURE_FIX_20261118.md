## JSON失败的根因

用与原失败请求完全相同的请求哈希重放，HTTP200、`finish_reason=stop`，但JSON第16行第65列报 `Expecting ',' delimiter`。第二次诊断也在同一位置复现。返回内容在一条 `text` 字符串中使用了中文左引号和未转义的英文双引号，例如：

```text
"text": "服用“药物甲10mg"后缓解。"
```

英文双引号提前结束JSON字符串，随后“后缓解”成为非法语法。这次重现不是输出token耗尽或网络错误；输入原文的中文引号本身成对，混用发生在生成结果中。历史四条响应未保存，不能逐条断言具有完全相同的字符错误，但相同请求已两次复现这一故障。

程序原来第二次只是原样重发提示词和seed，没有指出格式问题。现在仅在JSON解析或必需段落校验失败后，追加明确的格式纠正要求：转义字符串内双引号、输出完整对象及三部分、保留原始事实/截止点/来源/固定字段。不自动猜补JSON或改写医疗事实，仍受原每例最多2次调用与请求/时间预算约束。首次请求及v2提示词文件不变。

解析异常现在带JSON错误类型、行列位置；调用日志保存响应SHA-256、结束原因、内容类型与字符数，不默认保存完整病历响应。公开病例的原始诊断响应仅保存在本地忽略目录。

## 两条高等级告警的根因

原文逗号可能既分隔否定列表，也分隔新断言。旧规则在逗号处停止否定，随后默认按阳性处理，造成：

- cmbclin-019 的“糖尿病史”与生成的否定表述发生 `negation_flip`。
- cmbclin-026 的“恶心呕吐”与生成的否定表述发生 `negation_flip`。

开发上下文规则现在将否定后、逗号分隔、无明确谓词的短语保留为 `unknown`，产生中等级 `context_scope_ambiguous` 复核提示。不会直接延长否定范围，也不会把歧义当成明确阳性。显式否定、转折、时间/数值、主体切换、肯定谓词和无尿等固定表达保持各自含义。正式默认仍为legacy上下文。

对原有两例的既有生成文本做离线复核，目标高等级冲突均变为歧义复核；这不是新的临床正确性评分，也不表示其他待核事项已经解决。
