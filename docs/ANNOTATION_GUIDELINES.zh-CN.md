# MedTrace 参考数据标注指南

[English](ANNOTATION_GUIDELINES.md) | **简体中文**

## 1. 标签来源 —— 每个标签都带有其中一种来源，且从不被静默混用

| `status` | 含义 | 可否用作金标准？ |
|---|---|---|
| `verified_by_source` | 从数据集自带的专家/教科书答案中原样复制，未作修改 | 可以，限于其所回答的内容（注意其 `note` 字段） |
| `expert_reviewed` | 由项目临床医生撰写或校正，附审核人标识与日期 | 可以 |
| `rule_derived_unreviewed` | 由确定性规则产生（测量值、阴性项、鉴别诊断名称） | 仅可作为筛查替代指标；须按替代指标报告 |
| `model_generated_unreviewed` | 由任何 LLM 起草 | **不可以。** 在经审核升级之前，从不作为评分依据，从不计为参考 |

升级为 `expert_reviewed` 须满足：审核人已阅读来源、校正文本，并记录
`reviewer`、`date` 以及是否作了修改。两位审核人之间的分歧提交临床负责人裁定。

## 2. 标准化病例（输入）

- `case_id`、`record_cutoff`、`sources[{source_id, content}]`；`source_id` 在整个数据集中唯一。
- 来源文本保持逐字原样。不要校正错别字、单位或 OCR 损坏（例如 `×109/L`）；核验者会读取
  此类形式。不要翻译或概括。
- `record_cutoff` 是 `sources` 中所有内容均已确知的最晚时刻。若原始资料没有日期
  （教科书病例），则为 `null` —— 不要凭空编造。
- **泄漏规则。** `sources` 中绝不允许出现：病例标题或任何点明诊断的标签；出院诊断或最终
  诊断；手术、术中所见、术后病理；入院后给予的治疗及其反应；结局、随访。入院前的既往史
  应当保留（既往手术、入院时已可获得的院外治疗及结果）。
- 若某一句话混有入院时内容与后续内容，不要编辑它：将该病例标记为 `review_required`，由
  临床医生决定是拆分、删除该句，还是剔除该病例。
- 记录本身已陈述诊断的（例如入院时的活检结果）是正当的；将其标记为
  `diagnosis_stated_in_record`，以便诊断命中类指标跳过它。

## 3. 撰写参考首次病程记录（`expert_reviewed`）

字段：`case_features`、`diagnostic_discussion`、`plan`、`evidence`、`review_items`。

- **case_features** —— 仅包含来源所陈述的内容。带单位的值与记录完全一致，并各自注明时间
  点。阴性项保持阴性。未记录的项目为"未记录"，绝不写作正常。每行一条陈述，每条都注明
  支持该陈述的 `source_id`（一个或多个）。
- **diagnostic_discussion** —— 按问题组织，最紧急者在前：支持性发现、反对性发现、分级
  结论（明确 / 可能性大 / 可能 / 不能除外）、2–4 条针对该患者的具体鉴别诊断（各附支持与
  反对依据），以及仍属未知的内容。记录未能确立的诊断，绝不写成已确诊。
- **plan** —— 检查、治疗、监测；每一项都回应一个已记录的问题或一项已陈述的不确定性，并
  以建议的口吻表述。须对照已记录的过敏、用药、器官功能、妊娠、抗凝情况核查。
- **evidence** —— 为每一项重大事实性陈述给出 `{statement, source_ids}`。
- **review_items** —— 对决策有影响的缺失信息、来源之间的冲突、临床医生必须核实的任何
  事项。
- 另须列出 `must_not`：对本病例而言若出现即属严重错误的陈述（见 `CLINICAL_RUBRIC.md`）。
- 标注者可以查阅教科书答案，但不得从被隐去的入院后章节引入事实。

## 4. 事实级标注（用于抽取与核验测试）

每条事实：`source_id`、逐字的 `text`、`category`（主诉、病史、查体、检验、影像、用药、
过敏）、`polarity`（阳性 / 阴性 / 待定或未做 / 不确定）、`value`、`unit`，若已注明则含 `time`。
极性依文本而定，而非依临床预期："未扪及肿块"仅对该项检查为阴性。

## 5. 数据划分

由 `data_pipeline.quality.assign_splits` 分配（基于疾病标签 / 近重复簇的确定性哈希）。
`dev`：提示词与规则开发。`validation`：在变体之间做选择。`test`：一次最终的预注册比较。
病例从不在划分之间移动；新病例由同一函数获得其划分。
