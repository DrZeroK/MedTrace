# MedTrace 项目说明（测试版）

MedTrace 从入院资料生成住院首次病程草稿，输出病例特点、拟诊讨论、诊疗计划、依据及待核事项。用途限于教学、比赛和研究评测。输入和生成结果不能直接用于真实诊疗。

## 方法与改进

1. 解析资料截止点，按资料和句子过滤明确晚于截止点的内容；T0作为无日历映射的赛方标记保留。
2. 建立事实台账，汇总数字、单位、否定、待回报信息与可能冲突。
3. 使用固定v2提示词和A2流程生成带来源编号的陈述。默认temperature为0、seed为42，最多两次逻辑调用，第二次仅用于重生成无法解析或缺段的结果。
4. 校验数字、单位、否定、来源及完成/计划表述。无效引用被移除，未解决的问题进入待核事项。默认不开启额外模型修复调用。
5. 校验官方输入、完整医学分段、成功/失败结构与病例内引用。单例失败保留位置，整批完成后原子发布output.json，并导出可核对的run_log.json。

默认官方入口只从main.py旁的.env读取MODEL_NAME和完整ENDPOINT，使用无密钥HTTP调用；忽略开发环境的模型别名、路径、鉴权及代理。开发模式必须显式使用--development。

## 资源与复现

测试包内包含源码、两种语言的v1/v2提示词、依赖、输入样例、说明和SHA-256清单。当前默认不携带外部知识库或模型权重。经审核的可选知识库可以随包放入resources目录，运行时自动从该目录加载，不依赖开发机路径。

算法包和测试结果包由白名单构建。构建拒绝覆盖已有归档，原有包继续保留。提交清单记录源码提交号、提示词指纹和逐文件哈希；运行记录包含本次运行标识、时间、模型参数、病例映射、调用/重试次数、token用量及输入输出摘要。

## 验证和局限

自动化检查覆盖官方无参数入口、无效输入隔离、模型缺段重试/失败、鉴权与代理隔离、结果完整发布、日志关联和打包排除项。离线模拟结果证明工程流程，不代表指定模型的医学质量。历史公开数据实验及其限制保留在仓库docs/REPORT.md中，不作为当前官方成绩。

规则校验不能可靠判断临床推断是否正确，也不能发现所有遗漏。相对时间、复杂否定及缩写仍可能造成误判。seed不能保证不同硬件和模型版本逐字相同。指定模型、最终时限/预算、临床评阅及官方资源许可仍需赛前确认。
