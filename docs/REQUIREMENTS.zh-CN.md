# 比赛要求与验收边界

[English](REQUIREMENTS.md) | **简体中文**

主办方提供的汇总指南附录 3 定义了已实现的运行协议。主办方最新发布的版本优先。此前问答中关于命名的存疑之处，不能覆盖这一基于完整本地指南的实现。

| 要求 | 实现与回归覆盖 |
|---|---|
| Python 3.11、requires.txt、不带参数运行 main.py | CI 与隔离的包入口测试 |
| 仅从 main.py 同目录的 .env 读取 MODEL_NAME 与完整的 ENDPOINT | 官方解析器；受污染的工作目录/环境测试 |
| 无必需的密钥、Authorization、继承的凭据或代理 | 无密钥客户端与传输测试 |
| 固定使用根目录下的 input.json 与 output.json | 官方配置忽略环境变量中的路径覆盖 |
| 数组输入；case ID 为唯一非空字符串 | 任务级校验；退出码 2 |
| 有效的 cutoff、唯一的字符串 source ID、字符串 content | 逐例校验；失败记录保留在原位 |
| 完整的段落、evidence 与 review 字符串 | 严格的模型解析、最终结构检查与病例内引用检查 |
| 输出顺序与输入一致；支持失败与空输入 | 批量测试 |
| 整批完成后原子发布 | 官方模式从不发布中间结果；中断测试 |
| 本次运行的 run_log.json | 运行 ID、病例/请求时间戳、计数器、token 用量与 I/O 哈希 |
| 固定的提示词/参数版本与随机种子 | 代码默认值、提交清单、run_start 配置 |
| 合法、固定版本、已登记并随包分发的离线资源 | 默认不使用外部知识库；经校验的发布版本从包内加载 |
| 源码与结果对应 | SHA-256 清单与结果包检查会拒绝被更改的输出、过期日志与被更改的资源 |

开发配置需要 --development（或在评测模块中传入 development=True）。它保留既有实验功能；不会影响官方的无参数入口。

当前打包仅用于测试；队伍编号尚未分配。正式结果需要获授权的病例与真实完成运行的日志。模拟输出不是正式结果。

仍需外部验收：指定的模型/服务版本；最终的请求、病例与任务限额；token/调用/重试/并发预算；包大小与资源登记模板；临床审查；队伍资格与已签署的声明。默认值仅为测试设置。正式提交时，需按主办方模板渲染项目说明，并核实十页上限。
