## 2. 改动一：官方叙述段落改为散文式

改动内容：

- `medical_record.case_features`、`medical_record.diagnostic_discussion` 和 `medical_record.plan` 将各自的多条陈述拼接为一段。
- 陈述顺序、措辞、evidence 和待核事项均不变；不重写任何临床文本。
- legacy/开发输出仍保留编号列表。

改前（示意）：

```
1. 成人，乏力2周，活动后心悸。
2. 结膜苍白，双下肢轻度水肿。
3. 血红蛋白82 g/L，肌酐185 μmol/L。
```

改后（官方输出）：

```
成人，乏力2周，活动后心悸。结膜苍白，双下肢轻度水肿。血红蛋白82 g/L，肌酐185 μmol/L。
```

英文示例：

改前：

```
1. 68-year-old man with fever and cough for 3 days.
2. Temp 38.6 °C, HR 104 bpm.
```

改后：

```
68-year-old man with fever and cough for 3 days. Temp 38.6 °C, HR 104 bpm.
```

3. 你更倾向散文式、无编号换行，还是保留编号列表？如果选择无编号换行，文本不变，只去掉编号。
4. 是否有专科特有的格式要求，例如每个临床问题单独成段？

## 3. 改动二：诊断过度肯定进入待核事项

触发条件：

- 拟诊讨论中的陈述含确定性措辞：`确诊`、`明确诊断`、`诊断明确`、`诊断已明确`、`诊断成立`、`确定诊断`、`可确诊`；英文 `confirmed`、`definite/definitely`、`definitive`、`diagnostic of`、`certainly`。
- 资料中完全没有出现上述确定性提示。
- 该发现为中等严重度，不自动重写病历。

动作（2026-11-19 修订）：每条被标记的陈述生成一条面向临床的待核事项，使用以下固定话术：

- 中文：`记录中初步诊断的确定程度可能高于资料支持，请复核初步诊断表述。`
- 英文：`The note states the working diagnosis more definitively than the records support; review the working diagnosis.`

已收到结论（2026-11-19）：**修改后同意**。要求加入 `初步诊断` / `working diagnosis` 措辞；以上修订话术取代初稿。

触发示例（公开演示 DEMO001）：

- 资料：`入院初步判断为贫血及肾功能异常，原因待查；血红蛋白82 g/L，肌酐185 μmol/L。`
- 草稿讨论：`贫血诊断明确。`
- 预期：出现上述待核事项；病历不被自动改写。

反例：

- 资料：`贫血诊断明确；血红蛋白82 g/L。`
- 草稿讨论：`贫血诊断明确。`
- 预期：不出现 `overconfident` 待核事项。

已知限制：该检查是陈述级、通用规则；只要任一资料中出现确定性提示，整例的检查都会被抑制。它不区分主诊断与鉴别诊断。这样设计是为了减少误报，但是否可接受需由审阅人判断。

请审阅：

1. 该话术是否准确、不带评判、可执行？
2. `复核诊断表述` 是否是最合适的动作？是否应改为 `核对诊断依据` 或 `请结合资料复核诊断`？
3. 触发范围应覆盖讨论中的所有诊断陈述，还是只覆盖主诊断？
4. 应作为待核事项（当前行为），还是应触发重写/删除？当前流程不会自动改写临床措辞。
5. 是否有应排除的误报场景，例如指南定义的诊断标准、病理已确诊的诊断？
6. 中等严重度是否合适？当前行为是提示复核，不阻断病历生成。
