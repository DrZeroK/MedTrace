# MedTrace model, resource and data declarations (test version)

**English** | [简体中文](DECLARATIONS.md)

- **Model and version:** Official mode calls only MODEL_NAME and ENDPOINT specified by the organiser's .env, and carries no model weights. There is currently no measured record against the designated service; the actual model version must be confirmed by the organiser. Defaults are temperature=0 and seed=42; the parameters are fixed with the source code and written to the run log.
- **Retrieval resources:** No external knowledge base by default. The bundled prompts and deterministic verifier rules are project code, governed by the hashes in the submission manifest. Any optional knowledge base must first pass source, licence and review checks, then be packaged together with its version manifest; unreviewed textbook indexes and knowledge drafts are not distributed with the package.
- **LLM use:** Development of this project and revision of its documentation use AI coding assistance; at run time the designated model produces drafts, and the program performs parsing and rule verification. Generated results that have not been reviewed by a physician are not treated as clinical conclusions. Historical development used non-designated models on public data such as CMB-Clin; those results are not official evaluation results.
- **Draft data-use commitment:** Organiser practice cases and official cases are used only for the competition and evaluation within the authorised scope; they are not sent to third-party models, online search or embedding services, not distributed externally, test answers are not cached, and official results are not manually rewritten case by case. By default the submission package contains no development data, real .env or development logs.
- **Material authenticity:** Simulated test outputs must state their source and do not replace official competition results; real run logs are retained, the best result among service retries is not selected, and clinical review or licences are not fabricated.

These technical declarations correspond to the current implementation. A team ID has not yet been assigned, and the current packaging is for testing only; formal commitments must be checked by the actual participating team and signed as required by the organiser. This document does not replace team-signed documents.
